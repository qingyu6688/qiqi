# 柒柒详细设计说明书

## 1.5.2 长度预算与任务规划快照

`TaskRecord.agentPlannedPrompt` 是可选的单张规划快照，不含客户端附加原话和固定设定。新任务生成和重试均保留该字段，备份沿用完整任务序列化，无数据库结构迁移。历史描述优先读取快照；没有字段的旧任务只在组装上下文时按既有附加段分隔符提取，不重写已保存提示词。

历史引用按实际 JSON 转义后的字符数计入 48000 字符历史预算。未附像素的描述最多 200 字符，附像素的最多 1200 字符。描述优先占用不超过一半历史预算，按从旧到新的顺序删除描述属性，为近期对话留出空间；编号、已删除图片占位及分支范围不改变。预算根据当前消息实际编码长度自适应，仍使用 144000 字符整体保护上限，并为范围提示预留空间。

`textExcerpt.ts` 为历史消息和生图补充材料提供包含标记的首尾摘录。对话生图正文上限为 30000 减去 512 字符协议预留。原话先限制到 2000 字符，仍超出时依次缩短原话、对话设定、全局偏好，原话在进一步压缩时至少保留短段首尾。规划原文始终完整，无法容纳则本机阻止请求。批量任务在创建卡片和发送图片请求前统一检查；历史任务重试也检查长度，避免不透明地改写旧快照。

逐参考图快捷路径仅提供每张的参考范围，原话由同一组装函数附加一次。标准 Images / Responses 接口的防改写及尺寸提示也在预留预算内；不假设所有第三方网关具有相同长度上限。


## 1.5.1 提示词与上下文

`AgentConversation.instructions` 保存单个对话设定，`AppSettings.agentCustomInstructions` 保存全局偏好。两者均为可选字符串，归一化时去除首尾空白并限制为 8000 字符；旧数据按空值处理，沿用现有 SQLite JSON 记录及备份流程，无表结构迁移。完整备份导入会恢复显式存在的全局指令和多图方案字段，缺字段或无效字段沿用本机值；单独导入 API 配置不改变这两项创作偏好。

`agentGuidance.ts` 合并固定指令，优先级为当前明确要求、对话设定、全局偏好。文本规划通过 Responses 的 instructions 每次发送，混合及客户端逐图请求则写入任务提示词；单张重试沿用该快照。服务商改写保存在 revisedPromptByImage，不覆盖任务提交时的提示词。

`agentImageReferences.ts` 在每张计划后附本轮原话并限定本张范围，引用解析在附原话前执行。无显式引用时使用当前轮参考图，逐图对应的快捷队列保持各自一张参考图。历史图片预算只影响像素，引用编号及已有提示词独立保留；长文字摘录同时保留首尾，完整本地数据不变。

`AppSettings.galleryImageVariation` 与任务同名可选字段记录 preserve/vary。缺省 preserve；提交时快照入任务，同步多图、异步逐图和重试使用相同策略。原有多 Key 分配、并发上限和独立图片规则保持有效。


## 回复进度与多图稳定性

- `AgentRoundProgress` 每秒刷新本轮已用时间，结束后以 finishedAt 固定总用时。阶段由连接状态、文字和实际图片任务推导，不估算生图百分比或完成时间。
- 图片进度条表示处理完的任务数；旁边分别显示成功、失败、生成中、排队和已停止的张数。重试轮次使用 startedAt，读取旧数据时回退 createdAt。
- `settleWithConcurrency` 保留输入顺序及每项成功或失败结果。对话和同步多图使用两路请求；异步画廊多图也将单次图片批次限制为两路，批量提示词的原有配置继续生效。
- 对话批量任务先创建排队记录，实际轮到任务时才记录 startedAt 并启动接口超时。每张成功后立即保存，失败及时更新卡片，停止后排队项不再调用接口。
- Rust HTTP 错误额外返回 retryable。只有 reqwest 确认连接阶段失败、地址仍为原始请求且属于临时握手或连接中断时才允许重试；证书错误和重定向后失败排除。前端等待 1 秒、2 秒后最多重试两次，停止和超时可以中断等待。
- 浏览器网络错误无法确认是否已发送，保持不自动重试。HTTP 错误和收到响应后的断流均不自动重发，避免额外计费。

## 独立多图、比例与对话数量

- `independentImages.ts` 为画廊每次单图请求添加序号和完整画面约束，原始提示词仍保存在任务记录中。同步接口多图各自以 n=1 请求，保留质量、参考图、遮罩和部分失败结果。
- 异步服务商在提交时拆为独立任务，`independentImage` 记录原数量与从零开始的序号。每个任务拥有自己的服务商任务 ID；重试沿用序号，复用配置恢复原始数量。
- `outputImageSize.ts` 计算 contain 布局，完整绘制在目标像素尺寸的 Canvas 中。仅尺寸不一致时重新编码；PNG/WebP 的透明输出保留透明补边，其余补白。
- `sizeOriginalImages` 与主输出按位置对应，记录尺寸适配前的图片。引用检查、清理、重试覆盖和 ZIP 备份均包含该字段，无需改变数据库表结构。
- `agentImageCount` 默认 auto，手动数量规范到 1–10。手动模式只提供相应条目数量的图像批量工具；已发起的任务计入数量，失败或删除不会自动触发额外图片请求。
- 自动模式沿用原有对话工具和上下文流程。API 地址、Key、独立 API 关联及登录方式不因本次更新而改变。

## 图生图与文本 API

`InputBar` 的图生图主按钮直接打开原有文件选择器，旁边独立下拉按钮保留拍照、图片链接、画板。参考图沿用输入草稿、去重、数量上限、遮罩处理与已有任务链路。

`TextApiSettingsTab` 从现有 profiles 中选择 Responses 文本配置，局部记录正在编辑的配置 ID，复用 `ApiModelPicker`。编辑的名称、地址和 Key 先写设置草稿，失焦或模型选择时保存；新增和关联均不改变 `activeProfileId`。关联写入混合模式及文本、图像配置 ID，继续复用原来的上下文和工具调用实现。部署预置配置的可见范围与锁定规则继续生效。

## 上下文生图

1. 对话由消息和轮次组成，每个轮次记录父轮次及输入、输出图片。
2. 发送时根据当前轮次追溯活动分支，不混入其他分支。
3. 历史文字、工具结果和已生成图片重新组装进请求；图片以真实图片内容和引用标记关联。
4. 混合模式中，对话模型负责理解上下文及选择参考图，图像接口负责具体生成或编辑。
5. 新建对话使用独立轮次树，历史对话保留，可继续使用。

## 品牌及兼容

显示名称为柒柒，包版本为 1.0.0。桌面标识为 `local.qiqi.studio`，新导入链接使用 `qiqi://`。继续识别旧 `gpt-image-playground://` 链接；现有存储键和数据库名称保留，避免仅因改名丢失本地数据。安装在独立目录，避免与原应用共用 data。

## 更新来源隔离

发布列表缓存按柒柒配置的仓库区分，避免读到原应用缓存。未配置更新源时不发网络请求，界面显示本地版本状态。开源来源链接仅用于署名和许可证，不作为产品主页、更新源或桌面下载入口。

## 界面说明

对话入口使用“对话生图”。空对话和设置页说明本机保存与独立上下文。原赞助弹窗调整为备份提醒，继续复用现有弹窗优先级与关闭逻辑。

1.0.1 在共享前端中增加猫咪装饰组件：导航使用小猫头，画廊和对话空状态使用猫头与爪印，模型读取按钮和关于页加入小猫爪。图案使用 SVG 与 currentColor，不引入图片生成或新依赖；浅色采用 Logo 相近的暖棕色，深色使用更亮的同色系。装饰设置 aria-hidden、focusable=false 和 pointer-events:none，窄屏隐藏导航及关于页的次要装饰。

## 模型发现

sub2api 与 OpenAI 兼容配置调用 `GET /v1/models`，使用当前配置的 Bearer Key；兼容标准 data 数组及常见模型数组。列表去重，支持搜索、多选和首页切换。读取列表仅保存在组件内存，选中的 ID 沿用既有配置格式持久化。

修改 Key、地址或服务商时清除旧列表并取消请求，迟到响应不会更新新配置。未返回模型、无权限、无效 Key、网络错误、非 JSON 和超时都有对应提示；旧配置模型不在当前列表中时提醒重新选择。没有根据模型名字猜测后端能力。

桌面请求复用 Rust HTTP 层；网页可直连或使用现有代理。Docker 仅为 `/api-proxy/models` 增加 GET 放行，其他路径仍保持原请求方法限制。fal.ai 与自定义非兼容供应商沿用原来的配置方式。
